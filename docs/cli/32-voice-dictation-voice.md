# 语音听写 (/voice)

用语音代替键盘输入 prompt。

## 概述

`/voice` 命令（别名为 `/record`）从麦克风录制音频，并在你说话时将实时转录文本直接流式传输到 prompt 输入框中。你也可以在任何时候使用 F5 键开始听写。

语音听写会将文本写入 prompt 输入框；它**不会**自动提交你的 prompt。当你停止录音时，转录文本会保留在 prompt 输入框中，就像是你亲手打字输入的一样，方便你在准备好之后进行编辑、补充和提交。

> [!CAUTION]
> **请先退出登录并重新登录。** 语音听写需要登录时授予的更新身份验证权限。如果你的活跃会话是在语音听写功能推出之前认证的，转录将会失败。请运行 `/logout`，重新登录并重试。这是一个一次性的设置步骤。

## 听写 Prompt

若要在终端中听写 prompt，请按照以下步骤操作：

1.  按 F5 键，或者在 prompt 输入框中输入 `/voice` 并按 Enter。
2.  等待 prompt 下方的 statusline（状态行）从 **Connecting...** 转变为 **Recording**。
3.  对着麦克风清晰地说话。随着转录服务处理音频，临时文本将显示在 prompt 输入框中并持续更新。
4.  按 Enter 键（或 F5）停止录音，并将转录文本保留在 prompt 输入框中。

当录音会话处于活跃状态时，prompt 下方的 statusline 会显示已录制时长及可用的快捷键操作：

```
● Recording 0:07  enter or f5 to insert · esc to discard
```

### 听写控制

以下快捷键用于控制活跃的听写会话。录音期间将忽略所有其他按键，以防止误输入：

| 按键 | 操作 |
| :-- | :-- |
| Enter（或 F5） | 停止录音并将转录文本插入 prompt 中。 |
| Esc | 放弃录音并恢复先前的 prompt 内容。 |
| Ctrl+Z _（事后）_ | 将整个听写内容作为单次撤销操作完全恢复。 |

如果在开始听写前 prompt 输入框中已有文本，转录文本将追加到现有文本之后，而不是替换它。

> [!NOTE]
> F5 键支持重新映射。使用 [`/keybindings`](/docs/cli/reference#default-keybindings) 将 `voice.start_dictation` 绑定到不同的快捷键；屏幕上的提示会自动更新以反映你的自定义快捷键设置。

### 可用性

语音听写受以下操作条件限制：

*   听写需要交互式 TUI（终端界面）会话，在非交互式打印模式（`--print`）下处于禁用状态。
*   商业或企业账户目前不支持语音听写。

## 基于 SSH 的远程语音输入 (Voice over SSH)

当 CLI 通过 SSH（Secure Shell）在远程机器上运行时，远程环境无法直接访问你本地的音频硬件。`mic-serve` 子命令通过将本地麦克风的音频流式传输到本地环回套接字（local loopback socket），再通过反向 SSH 隧道转发至远程 CLI，从而解决了这一问题。

本地机器和远程主机上都必须安装 Antigravity CLI。

### 1. 提供本地麦克风服务

在本地机器上启动麦克风服务器：

```
agy mic-serve
```

在听写时保持此进程处于运行状态。默认情况下，`mic-serve` 监听在 `127.0.0.1:4713` 上，并将来自默认输入设备的音频流式传输给已连接的客户端。你可以在后台任务、`tmux` 窗格或独立的终端窗口中运行它。

若端口 `4713` 已被占用，可以指定 `--addr` 参数绑定自定义端口：

```
agy mic-serve --addr 127.0.0.1:<UNUSED_PORT>
```

> [!CAUTION]
> **请保持 `mic-serve` 监听在 `localhost` (`127.0.0.1`)**。麦克风服务器专门用于通过 SSH 隧道转发的本地连接。请将其绑定到环回地址，以防网络上的外部设备访问音频流。

### 2. 开启反向隧道

在本地机器上，通过建立 SSH 反向隧道将本地音频端口转发到远程机器：

```
ssh -R 24713:localhost:4713 <remote-machine>
```

在听写期间隧道必须保持活跃。若要在不维持交互式 shell 会话的情况下在后台运行隧道，请在 `ssh` 命令中使用 `-f` 和 `-N` 参数。例如：

```
ssh -f -N -R 24713:localhost:4713 <remote-machine>
```

### 3. 使用 `ANTIGRAVITY_MIC` 启动 CLI

在远程 SSH 会话中，将环境变量 `ANTIGRAVITY_MIC` 设置为转发的隧道端口并启动 CLI。例如：

```
ANTIGRAVITY_MIC=localhost:24713 agy
```

如果远程主机是 Windows 并且使用的是 PowerShell，请设置环境变量并启动 CLI：

```
$env:ANTIGRAVITY_MIC = "localhost:24713"; agy
```

或者，如果远程主机是 Windows 并且使用的是 Windows 命令提示符（`cmd.exe`）：

```
set ANTIGRAVITY_MIC=localhost:24713 && agy
```

在 CLI 中，按 F5 或使用 `/voice`，然后对着麦克风说话。当 CLI 发起音频连接时，本地的 `mic-serve` 进程会输出一条确认日志。例如：

```
Recording for 127.0.0.1:54134.
```

### 4. 验证隧道连接

如果听写时 `mic-serve` 的输出中没有出现连接日志，可以通过在远程主机上捕获原始音频样本来测试转发端口是否可达。例如：

```
timeout 5 nc localhost 24713 > /tmp/mic.raw
```

如果 `/tmp/mic.raw` 以约 32 kB/s 的速率积累数据，则说明通过反向隧道的音频流传输正常工作。

## 故障排查

*   **转录失败并提示权限消息**：你存储的凭据早于语音听写功能的支持。执行 `/logout`，重新登录以刷新权限，然后再重试。请注意，商业或企业账户无法使用语音听写。
*   **没有转录任何内容且录音静音**：当前终端进程缺少操作系统麦克风权限（本地会话为运行 CLI 的终端，SSH 会话为运行 `agy mic-serve` 的终端）：
    *   **macOS**：同意系统权限弹窗，或在 **系统设置 → 隐私与安全性 → 麦克风** 中授予访问权限。使用 Cmd+Q 重启终端以应用更新后的权限。
    *   **Windows**：在 **设置 → 隐私和安全性 → 麦克风** 中启用麦克风访问权限，并确保开启 **允许桌面应用访问你的麦克风**。
*   **通过 SSH 连接时立即失败**：转发的端口上没有进程在监听。请验证本地机器上的 `agy mic-serve` 和 `ssh -R` 反向隧道是否都在运行。
*   **听写提示麦克风服务器已关闭连接**：服务器进程意外终止或网络隧道断开。检查本地机器上 `agy mic-serve` 的输出以获取详细的错误诊断信息。
*   **使用了错误的麦克风**：`mic-serve` 从系统默认输入设备捕获音频。请在 **系统设置 → 声音 → 输入** (macOS) 或 **设置 → 系统 → 声音 → 输入** (Windows) 中核实你的默认输入硬件。
*   **转录断断续续或掉字**：音频未压缩通过 SSH 隧道流式传输；SSH 连接的高延迟或带宽饱和可能会导致音频数据包丢失。
